# منارة الطريق — Web App

تطبيق Next.js حقيقي (وليس HTML ثابت) يطابق الشكل والمحتوى الأصلي، لكن مع:
- توجيه فعلي بروابط حقيقية لكل قسم (بدل تبديل JS داخل صفحة واحدة)
- نظام تسجيل دخول/تسجيل حقيقي عبر Supabase Auth (بريد إلكتروني + Google + GitHub)
- نموذج تواصل حقيقي يحفظ الرسائل في قاعدة البيانات
- تصميم بصري مخصص (نظرية "المنارة": خلفية داكنة + إشعاع ذهبي دوّار في الصفحة الرئيسية)

## التشغيل خطوة بخطوة

### 1) ثبّت الحزم
```bash
npm install
```

### 2) أنشئ مشروع Supabase (مجاني)
اذهب إلى https://supabase.com → New Project → انسخ:
- Project URL
- anon public key
من: Project Settings → API

### 3) أعد تسمية ملف البيئة
```bash
cp .env.local.example .env.local
```
وضع فيه القيم الحقيقية من الخطوة السابقة.

### 4) فعّل تسجيل الدخول عبر Google/GitHub (اختياري)
Supabase Dashboard → Authentication → Providers → فعّل Google و GitHub وأدخل بيانات الـ OAuth الخاصة بك.
لو مش عايز تفعّلهم دلوقتي، البريد الإلكتروني وكلمة المرور شغالين بدون أي إعداد إضافي.

### 5) طبّق الجداول على قاعدة البيانات
في Supabase Dashboard → SQL Editor → افتح ملف `supabase/migrations/0001_init.sql` من هذا المشروع، انسخ محتواه، وشغّله. هذا ينشئ:
- جدول `profiles` (يتكوّن تلقائيًا عند تسجيل أي مستخدم جديد)
- جدول `contact_messages` (لتخزين رسائل صفحة "اتصل بنا")
- سياسات RLS الأساسية على الجدولين

### 6) شغّل المشروع محليًا
```bash
npm run dev
```
افتح http://localhost:3000

## ما الذي تغيّر عن ملف الـ HTML الأصلي ولماذا
- **التنقل:** بدل تبديل الأقسام داخل نفس الصفحة عبر JavaScript، كل قسم أصبح صفحة حقيقية (`app/<section>/page.tsx`) لها رابط مستقل يمكن مشاركته أو فتحه مباشرة أو فهرسته في محركات البحث.
- **تسجيل الدخول:** مضاف بالكامل (لم يكن موجودًا في النسخة الأصلية) عبر Supabase Auth الحقيقي — وليس نموذج وهمي.
- **نموذج التواصل:** أصبح تفاعليًا فعليًا، يرسل البيانات إلى `app/api/v1/contact/route.ts` ويُخزّنها في قاعدة البيانات، بدل عرض نص ثابت فقط.
- **البنية البرمجية:** تتبع Clean Architecture المحددة في `docs/spec-kit/03-architecture.md` — مثال كامل على ذلك في `features/contact/`.

## الخطوة التالية
هذا يغطي الشكل والمحتوى + تسجيل الدخول + نموذج تواصل، وهو ما يوازي تقريبًا نهاية **Phase 2** من خارطة الطريق (`docs/spec-kit/09-roadmap.md`). الأقسام التي تحتاج بيانات حقيقية (المستودع الرقمي، أدوات الباحث، الفعاليات، المجتمع) لسه محتوى ثابت (placeholder) لحد ما نبني الجداول والـ Services الخاصة بيها في المراحل القادمة.
